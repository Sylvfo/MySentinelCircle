3. SECURITY
=========================================================================

[ ] nginx: HSTS header
[ ] Frontend served as a production build (npm run build) behind nginx,
    not the Vite dev server (today: proxy_pass http://frontend:5173).
    Needed anyway for production, and before step 3 below.
[ ] nginx: Content-Security-Policy header. It blocks any script that
    doesn't come from our own site, which protects the login token kept
    in the browser (localStorage) if an injection flaw ever appears.
    1. In nginx/nginx.conf, right after the "Referrer-Policy" line, add
       (report-only first: it blocks nothing, it only lists in the
       browser console what it would block):

       add_header Content-Security-Policy-Report-Only "default-src 'self'; script-src 'self' https://accounts.google.com/gsi/client; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://accounts.google.com/gsi/style; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: blob: https://*.googleusercontent.com https://*.gstatic.com; connect-src 'self' https://accounts.google.com/gsi/; frame-src https://accounts.google.com/gsi/; frame-ancestors 'self'; object-src 'none'; base-uri 'self'; form-action 'self'" always;

       It allows: our own scripts, data and images; Google Fonts; the
       "Sign in with Google" button; photos (blob: URLs). 'unsafe-inline'
       in style-src is for React's inline styles only (no scripts).
    2. Rebuild nginx (the config is copied into its image):
         docker compose up -d --build nginx
    3. Use the app with the browser console open (F12): login (also with
       Google), messages with a photo, profile photo, an alert with its
       map. Every "[Report Only] Refused to ..." line means the policy
       needs adjusting.
    4. Once the console is clean AND the frontend is a production build
       (the Vite dev server injects an inline script that an enforced
       policy would block): rename the header to
       Content-Security-Policy to enforce it.
    5. When the fonts are hosted by us (line below), remove
       fonts.googleapis.com and fonts.gstatic.com from the policy.
